# Аналитика посадочной страницы квалифицированных лидов

## Цель

Отделить интерес к странице от реальной готовности обсудить тест. Основная конверсия — успешно принятая заявка. Промежуточные события показывают, где пользователь теряет смысл или доверие.

## Воронка

1. `page_view` — страница открыта.
2. `story_stage_view` — пользователь впервые увидел один из восьми смысловых этапов.
3. `cta_click` — нажат призыв к действию; сохраняются источник и назначение кнопки.
4. `form_open` — форма открыта.
5. `form_start` — пользователь начал заполнять форму.
6. `form_submit_attempt` — отправка начата; сохраняются способ связи и запрошенный объём.
7. `form_submit_success` — заявка принята сервером.
8. `form_submit_error` — ошибка проверки или доставки.
9. `form_close` — форма закрыта без обязательной отправки.

Дополнительно `motion_toggle` показывает, сколько пользователей отключают движение.

## События, которые считаем ключевыми

- Досмотр оффера: `story_stage_view` со `stage = 8`.
- Интерес к тесту: `cta_click` с `target = form`.
- Начало заявки: `form_start`.
- Конверсия: `form_submit_success`.
- Потеря после открытия: `form_close` без `form_submit_success` в той же сессии.

## Срезы рекламных кампаний

Для первой закупки достаточно обязательных меток:

- `utm_source` — рекламная система, например `yandex`;
- `utm_medium` — тип трафика, например `cpc`;
- `utm_campaign` — единое имя кампании: продукт, регион и гипотеза.

Рекомендуемый формат кампании: `qualified_leads_<region>_<hypothesis>_<yyyy_mm>`.

`utm_content` и `utm_term` сохраняются вместе с заявкой, но пока не входят в агрегированную таблицу событий. Поэтому первичное сравнение объявлений ведём по source / medium / campaign, а детализацию до объявления — по заявкам.

## Базовые показатели

- Досмотр = уникальные сессии со stage 8 / уникальные page view.
- CTR основного CTA = уникальные сессии с CTA на форму / уникальные page view.
- Открытие → начало = form start / form open.
- Начало → заявка = form submit success / form start.
- Общая конверсия = form submit success / page view.
- Ошибки = form submit error / form submit attempt.

Сравнивать нужно уникальные сессии, а не количество событий: один пользователь может открыть форму несколько раз.

## Приватность и безопасность

- В события не передаются имя, телефон, Telegram, город или свободный текст.
- Сервер принимает только заранее разрешённые названия событий и значения свойств.
- Адрес страницы очищается от query-параметров, referrer — до origin.
- Диапазон объёма ограничен от 10 до 1000.
- Тесты формы используют перехват запросов; реальные заявки и Telegram-сообщения не создаются.

## Перед рекламным трафиком

1. Подтвердить запись всей воронки на тестовой сессии без персональных данных.
2. Зафиксировать одну схему UTM для всех объявлений.
3. Проверить мобильную версию на реальном телефоне и медленной сети.
4. Запустить ограниченный бюджет и не менять оффер до появления минимальной выборки.
5. После выборки менять только один элемент за итерацию: первый экран, доказательство или CTA.
